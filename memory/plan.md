# 部署计划

1. 检查 HK-AK 的 Docker、TUN、资源、现有容器与端口。
2. 使用项目的图形版 aTrust，持久化登录配置，配置自动重启。
3. VNC/noVNC、代理及浏览器回调端口仅绑定 127.0.0.1，通过 Termius 隧道访问。
4. 检查容器状态、日志和代理服务；用户完成钉钉扫码后验证 VPN。
5. 保存实际部署说明、验证记录与开发日志，提交并推送。

范围：部署配置和说明、memory、docs/CHANGELOG.md。保留现有通用 Compose 和应用代码。

## 每分钟访问校内地址

1. 复用 `start.sh` 的 `keep_pinging_url`，在学校 Compose 中设置 `PING_ADDR_URL=http://10.130.10.75/`、`PING_INTERVAL=60`。
2. 新增独立的 ZJU-Connect 1.3.1 Compose 和 TOML 示例，使用 aTrust 密码认证；复用客户端内置每 60 秒 HTTP 保活，无需新增循环脚本。
3. 凭据和会话文件加入忽略规则；代理保持 127.0.0.1 的 1080、8888，保留图形版作为恢复点。
4. 验证 Compose、TOML 和实际学校认证信息；缺少账号密码时不声称登录成功。
5. 更新部署说明、验证记录和开发日志，提交并推送。

影响范围：学校部署配置和示例、部署说明、忽略规则和持久记录；不新增循环脚本或公共导出，不更改现有代理端口和登录数据。

账号密码登录：用户已确认 VPN 门户直接密码认证，并要求修改项目；采用支持 aTrust 的 ZJU-Connect。实际服务器暂不切换。

## 本地真实凭据验证

1. 安全解析用户填写的本地配置，原生客户端使用独立测试状态目录、本机代理端口和受限日志。
2. 用户已允许查看学校验证码；完成验证码后验证密码认证、HTTP / SOCKS5 访问目标资源。
3. 重启恢复会话，验证无需重复验证码，并观察两次相隔 60 秒的自动保活。
4. 结束测试进程，清理包含会话详情的临时调试日志，保存脱敏结果，提交并推送文档。服务器不作变更。
